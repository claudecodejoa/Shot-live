# 슛폼 라이브

폰 카메라로 농구 슛을 비추면 슛마다 **고칠 점 하나**를 화면·음성으로 알려주는 웹앱(PWA).
분석은 전부 폰 안에서 돌아간다 (TensorFlow.js + MoveNet). 앱: https://claudecodejoa.github.io/Shot-live/

- 사용: 폰을 세워 고정 → 카메라 시작 → 림 왼쪽 끝·오른쪽 끝 탭(성공률까지) 또는 "건너뛰기 · 폼만 분석" → 슛
- 사람이 여럿이면 슈터를 길게 눌러 고정. 상단 아이콘: 림 다시 지정 · 슈터 고정 · 메뉴(요약, 녹화, 음성, 판정, 키, 모델)
- 설치: 안드로이드 크롬 메뉴 → 홈 화면에 추가 / 아이폰 사파리 공유 → 홈 화면에 추가

## 공통 기준 (모든 슈터에게 같은 기준만 평가)

`index.html`의 `measureShot` → `gradeShot`. 기준값은 `TH` 상수. 오른손/왼손, 카메라가 정면/측면인지는 자동 판별한다.
측정 못 하는 각도의 항목은 "측면에서", "림 지정 시"처럼 비활성으로 표시한다.

| 항목 | 기준 | 촬영 | 근거 |
|---|---|---|---|
| 좌우 직선 | 림 중앙 ±10cm | 정면 + 림 | Wissel 교정표, 좌우 흔들림↔정확도 r=0.80 (J Sports Sci 2022) |
| 아치(발사각) | 45~60° (권장 45~55) | 측면 | 물리 모델 ~52°, 들어간 슛이 발사각 더 큼 (Wang 2026) |
| 깊이 | 중앙보다 −5~+12cm | 측면 + 림 | 중앙보다 살짝 뒤 (Noah) |
| 하체·릴리즈 | 하체 사용(앉기/점프 ≥5cm), **하강 중 릴리즈만 경고** | 공통 | 정점 전 릴리즈는 스타일로 인정 |
| 균형 | 착지 밀림 ≤15cm, 몸 기울기 ≤10°, 무게 쏠림 ≤10cm, 무릎 모임 | 공통/정면 | 잘 쏘는 사람은 릴리즈 때 상체 거의 수직 (2023 markerless FT) |
| 팔로스루(보조) | 슛하는 손목이 어깨 위에 ≥0.35초 | 공통 | 코칭 공통 |
| 준비 동작(보조) | 딥: 공을 가슴 아래로 내렸다 올리기 | 공통 | Penner 2021, 딥 넣으면 약 7~9%↑ |
| 일관성 | 최근 7개 릴리즈 타이밍 SD ≤0.07초, 발사각 SD ≤3°, 좌우 SD ≤8cm | 3개부터 | ISBS 2008 coordination variability |

평가 안 함(스타일, 참고 값만 표시): 셋포인트 높이, 팔꿈치 각도, 무릎 깊이, 점프 높이, 템포.

### 결과 → 폼 원인 → 고칠 점
좌우·발사각·깊이는 결과만 말하지 않고, **같은 방향을 가리키는 폼 신호**가 있을 때 그걸 원인으로 붙인다 (`lateralFix`, `launchFix`, `depthFix`).
- 슛하는 손 쪽으로 빗나감 + 팔꿈치 벌어짐 → 팔꿈치를 림 쪽으로 / 반대쪽 + 공이 몸 바깥에서 출발 → 귀와 어깨 사이에서 시작
- 빗나간 방향 = 착지 밀린 방향 / 상체 기운 방향 → 제자리 착지 / 상체 세우기, 원인이 없으면 발끝·어깨를 림 정면으로
- 발사각 낮음 → 팔을 위로 뻗기 / 팔꿈치 끝까지 펴기 / 상체 세우기 (Wang 2026: 들어간 슛이 팔꿈치 펴짐·어깨 굴곡·릴리즈 높이 모두 큼)

### 슛당 피드백 1줄 우선순위
1. 실패 방향(좌우/깊이) 2. 공통 기준 위반(아치 → 하체·릴리즈 → 균형 → 팔로스루) 3. 일관성 4. 딥(보조) 5. 칭찬

## 개발
- 테스트 훅: `SHOT_STEP`(프레임 단위), `SHOT_T0/T1`(구간), `SHOT_BACKEND='wasm'`+`SHOT_BACKEND_SRC`, `SHOT_RIM`, `SHOT_SHOOTER`, `SHOT_DEBUG`, `__TEST_START(judge)`.
- `SHOT_STEP` 실행은 슛마다 `[raw]`(포즈+공 경로)와 `[eval]`을 콘솔에 남긴다. `[raw]`로 평가 엔진만 따로 다시 돌릴 수 있다 (`(EVAL-BEGIN)`~`(EVAL-END)` 주석 사이).
- 배포: `sw.js`의 `VERSION`을 올리고 `main`에 푸시 (GitHub Pages).
